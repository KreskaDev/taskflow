# Implementation Plan: Comments & @Mentions

**Branch**: `009-comments-mentions` | **Date**: 2026-07-01 | **Spec**: `specs/009-comments-mentions/spec.md`

**Input**: Feature specification from `specs/009-comments-mentions/spec.md`

## Summary

Adds a **comment thread** to tasks in **shared** projects (US-14.AS-01..AS-04). An **editor** or **owner** posts a comment on a shared-project task — it appears in the task's thread with author and timestamp (AS-01, FR-072); an author **@mentions** a current project member, notifying them (AS-02, FR-074); a **viewer** reads the thread but is presented with **no composer** and cannot post/edit/delete (AS-03, FR-061/067/072); and a comment's **author — and only the author — edits or deletes their own comment**, with the thread updating (AS-04, FR-075). This is the product's **first free-form user-content surface** and a **stored-XSS target** (Constitution XII — the centre of this slice's security posture).

This slice introduces **ENT-08 `Comment`** as its **own aggregate root** (`Comment : AggregateRoot<CommentId>`, server-minted UUIDv7) — **not** an owned child of `Task` (research R1): a comment has a lifecycle independent of its task, its own author grant, its own edit/delete surface, its own @mention set, and emits its own domain event, so its consistency boundary is the single comment, not the task or the whole thread. Comments are **versionless / last-write-wins** (R2, Constitution Principle III) — **no** per-comment concurrency token and **`version_conflict`(409) is not used** by this slice. It ships **two new tables** (`comments` + the typed `comment_mentions` child collection) via one EF migration (`AddComments`).

Authorization is **CONSUMED, not originated**: this slice **reuses the slice-007 dispatch-by-visibility policy verbatim** (`ResolveEffectiveRole` / `RequireRole`) — comments live **only** on tasks in **shared** projects, so every read/write loads the parent `Task`, resolves its `Project.Visibility`, and dispatches onto the slice-007 membership + role branch (FR-065/066/067/068): **read = viewer+** (any current member; non-member → 404), **post = editor+** (viewer → 403). Edit/delete layer an **object-level authorship grant** (FR-075) **on top of** the role floor via a strict two-step gate — `RequireRole(Editor)` **FIRST**, then `author_id == caller` **SECOND** — so a non-author of any role (**including the project owner**) is denied 403, and because membership is resolved **live** in step 1 a former member is 404'd **before** the author check ever runs, making **FR-066 (membership loss revokes ALL) structurally beat FR-075 (author grant)** with no special case (R3/R4). An @mention is a **typed User-id token** (never scraped from prose, R6) whose candidacy is validated server-side against the **current** member roster; each post/edit raises a **`UserMentioned`** domain event (pure ids, delta-on-edit) to the Wolverine outbox (R7).

It **ships a migration** (`AddComments` — the `comments` + `comment_mentions` tables), so **FR-051 backup-before-migration is LIVE** (the slice-004/007/008 posture, NOT the slice-003/005 no-op): the automatic pre-migration backup and the CI `backup → migrate → restore-test` gate (Constitution VII) must actually execute against it. **No new error code** is added (R9) — `forbidden`(403), `not_found`(404), and `validation_failed`(422) are reused; `version_conflict`(409) is **unused** this slice — so the transformer `ErrorCodes` array and the web `ERROR_UX satisfies Record<ErrorCode, ErrorUx>` map stay **unchanged** and the exhaustiveness gate stays green with no edit.

What is **named but deferred**: the in-app **notification** the @mention triggers (notification center, live toast, mark-read, per-type preferences) is **slice 017** — this slice **raises** `UserMentioned` and registers a **no-op routable handler**, so 017 attaches additively (R7); **live propagation** of a remote comment into an open thread (SignalR, re-authorization/subscription eviction of a former member) is **slice 016** — this slice builds the **optimistic-paint** half now and names the reconciliation contract (don't clobber a pending local edit) for 016 (R13); the **author-anonymization erasure cascade** (author_id → tombstone) is **slice 015** — this slice **models** for it (nullable `author_id`, FK `ON DELETE SET NULL`, tombstone-safe read model) but does not build the cascade (R11); and the **user-facing comment restore/undo** is **slice 014** — this slice ships only the **soft-delete + scheduled `ReapDeletedComment` reaper** substrate (the `DeleteTask`/`ReapDeletedTask` mirror satisfying the Constitution-VII 30s-undo MUST), NOT the restore command/endpoint (R5).

## Technical Context

**Language/Version**: TypeScript (strict) on Node.js 22 LTS / Next.js 15 (App Router), React 19; C# 13 on .NET 9 / ASP.NET Core.

**Primary Dependencies**:
- Frontend (NEW this slice): **ONE new dependency — a vetted markdown renderer + HTML sanitizer** (e.g. `react-markdown` + `rehype-sanitize`, or `marked` + `DOMPurify` — exact package pinned at implementation, R8). This is a **conscious, called-out departure** from the slice-007 "no new web deps" posture: comments are the first free-form content surface and FR-098's literal "constrained safe subset (plain text + safe **markdown**)" requires a renderer with a **strict allowlist** (no raw HTML passthrough, no `<script>`/`<style>`/event handlers, safe URL schemes only). React's default text-escaping remains the backstop. Otherwise reuses TanStack Query v5 (a new **optimistic + rollback** `useCommentMutations` family on a `['tasks', taskId, 'comments']` key — the slice-002/004 recipe, NOT the slice-007 non-optimistic membership shape, R14), Zod 3 (body non-empty + length validation), openapi-fetch + openapi-typescript (regen), the slice-001 BFF proxy, the existing ARIA-live announcer + `ERROR_UX` map (unchanged — R9), and `date-fns` v4 + `date-fns-tz` v3 + `apps/web/src/lib/timezone.ts` for Warsaw-referenced relative time (NO new date library, R10).
- Backend (NEW this slice): **none** — reuses Wolverine + Wolverine.Http, EF Core + Npgsql, `WolverineFx.FluentValidation` (new `PostCommentValidator`/`EditCommentValidator` on the comment commands), the `ProblemDetailsMiddleware`, the transactional outbox (for `UserMentioned`, R7), the slice-007 `IResourceAuthorizationPolicy` (`ResolveEffectiveRole`/`RequireRole` — **consumed, not forked**, R3), the `SecurityHeadersMiddleware` (FR-099 — reused, R8). **No NodaTime** (relative-time display is a web concern; comment timestamps are plain UTC `timestamptz` — Constitution X). **No new error code** (R9).

**Storage**: PostgreSQL 17. **One migration** (`AddComments`): creates **`comments`** (`task_id → tasks(id) ON DELETE CASCADE`, `author_id → users(id) ON DELETE SET NULL` — nullable, the tombstone FK, R11; `body text`, `created_at`/`edited_at`/`deleted_at timestamptz` — `deleted_at` is the soft-delete tombstone for the Constitution-VII 30s-undo reaper, R5; indexes `(task_id, created_at)` + `(author_id)`) and **`comment_mentions`** (surrogate PK; `comment_id → comments(id) ON DELETE CASCADE`, `user_id → users(id) ON DELETE SET NULL`; UNIQUE `(comment_id, user_id)`; index `(user_id)`). **No DDL on `tasks` / `projects` / `project_memberships`.** Because a table ships → **FR-051 is LIVE** (Complexity Tracking).

**Testing**: xUnit (`Comment` behavior — `Post`/`Edit` stamp `edited_at` on every edit, `SoftDelete` stamps `deleted_at` versionlessly, the whole-mention-set replace, the **added-only** mention delta for `UserMentioned` — an edit whose mention delta is empty raises **no** event — and the versionless posture); Testcontainers-Postgres integration (every command/query through the real DB **with an allow AND a deny authorization test** per handler — Constitution VIII/IX + the governance gate) **plus the role × operation deny matrix** as first-class tests (SC-016): viewer-denied-post (403), viewer/non-author-denied-edit/delete (403), non-author-owner-denied-edit/delete (403), non-member-denied-read/post (404), former-member-denied-view/edit/delete (404), non-member-mention (422), empty/over-length body (422), plus the `UserMentioned`-raised assertion (`.Sent.MessagesOf<UserMentioned>()`), the **`DeleteComment` soft-delete** (stamps `deleted_at`, schedules ONE `ReapDeletedComment`, idempotent replay → 204 no-op, the thread read EXCLUDES the soft-deleted row) and the **`ReapDeletedComment` reaper** (hard-purges after the delay only if still-tombstoned at the scheduled instant — restore-aware/idempotent — the `ReapDeletedTask` mirror, R5); Vitest (comment body validation, the **optimistic** `useCommentMutations` surface incl. rollback, the safe-markdown render asserting an HTML/script payload renders **inert**, viewer-sees-no-composer gating); Playwright (E2E — AS-01..AS-04 + the edge cases: viewer-read-only, non-author-owner-denied, former-member-denied, empty/over-length rejected, sanitization payload inert).

**Target Platform**: Linux containers (Docker Compose) on Hetzner VPS; host Caddy for TLS. No infra change.

**Project Type**: Web application (monorepo: Next.js frontend + ASP.NET Core API).

**Performance Goals**: comment mutations are **optimistic** (R14) — post/edit/delete paint within one animation frame (Constitution III), the server reconciling under LWW without clobbering a pending local edit; server single-aggregate writes p95 <200 ms (the per-request authorization lookup is the reused slice-007 indexed `(project_id, user_id)` probe + a `comments(task_id, created_at)` thread scan). The thread read (`['tasks', taskId, 'comments']`) is lazily fetched when the task detail panel opens.

**Constraints**: authorization is **deny-by-default, dispatched by the PARENT project's `Visibility`** (FR-065) — the slice-007 policy **consumed unchanged**, never forked (R3); comments exist **only** on **shared**-project tasks (a null `ProjectId` / personal task → **404**, no comment surface — R3); edit/delete run **`RequireRole(Editor)` FIRST then author-equality SECOND** (R4) so FR-066 structurally beats FR-075; comments are **versionless / LWW** — no `version` field, no 409 (R2); **`DeleteComment` is a soft-delete** (stamps `deleted_at` + publishes a scheduled `ReapDeletedComment` +30s off the `comment-reaper` durable queue — the `DeleteTask`/`ReapDeletedTask` mirror satisfying the Constitution-VII 30s-undo MUST; version-free/idempotent; the user-facing restore is the slice-014 seam, R5); the caller is **always** `ICurrentUser.Id`, never the wire; an @mention is a **typed User-id token** validated against **current** members, never scraped from prose (R6); `author_id` is **nullable / `ON DELETE SET NULL`** (tombstone — the one FK that deliberately breaks house-style cascade parity, R11); **no new error code** (R9); output sanitization to the safe subset lives at the **web render boundary** (R8); CSP/security headers are **reused**, not built (R8).

**Scale/Scope**: ~10 users on a single shared instance (ASM-01/ASM-10); per-task threads are small (single/low-double digits). This slice adds one aggregate (`Comment`) + one child collection (`comment_mentions`), one migration, three commands (`PostComment`/`EditComment`/`DeleteComment`) + one thread query (`ListTaskComments`), one repository, one domain event (`UserMentioned`) + its no-op routable handler, the comment endpoints, the `CommentResponse` read model, and the web comment surface (a task detail panel hosting the thread + composer + mention picker + safe-markdown render). It **reuses** the slice-007 authorization policy and the slice-008 `TaskAssigned` outbox-event posture with **no modification** to either.

## Key Design Decisions

These summarize `research.md` (R1–R15).

### `Comment` is its OWN aggregate root, not an owned child of `Task` (R1)
A comment has a lifecycle **independent** of its task — its own creation/edit/delete, its own author grant (FR-073/075), its own @mention set, and it emits its own event — so its consistency boundary is the **single comment**, not the task or the whole thread. Modeling it as `Comment : AggregateRoot<CommentId>` (server-minted UUIDv7, mirroring `ProjectMembershipId`) means comment writes **do not touch `Task.Version`/`Project.Version`** (the parent is loaded read-only, for authorization only). This deliberately **inverts** slice-008 (`TaskAssignee` folded into `Task` under `Task.Version`) and slice-007 (`ProjectMembership` under `Project.Version`): those have no independent lifecycle, a comment does.

### Comments are versionless / last-write-wins — no 409 (R2)
Constitution Principle III mandates the thread reconciles under **last-write-wins**, and edit is **author-only** with **no cross-field invariant** a stale overwrite could corrupt — so a per-comment concurrency token would only add a 409 failure mode for no behavioral gain. `version_conflict`(409) is **not used** this slice (one fewer reused code than slice 007).

### Comment delete is a soft-delete + scheduled reaper — Constitution VII 30s-undo (R5)
A comment is task/project **data**, so its delete is covered by the Constitution-VII "undoable for a minimum of 30 seconds … by the original actor" MUST (the only carve-out is membership/role changes). `DeleteComment` therefore mirrors `DeleteTask`/`ReapDeletedTask` **precisely** (not a new mechanism): `Comment.SoftDelete` stamps `deleted_at` (versionless — no version bump), the command publishes a scheduled `ReapDeletedComment` (+30s) off the durable `comment-reaper` queue, and `ReapDeletedCommentHandler` (no caller, authz-excluded) hard-purges the row **only if** still-tombstoned at the scheduled instant (µs match — restore-aware/idempotent). Because comments carry no `version`, the task reaper's `Task.Version` 0-rows-DELETE race backstop has **no comment analog** — the instant match is the sole guard. The thread read filters `deleted_at IS NULL`, so a comment leaves the thread immediately (AS-04). The **user-facing restore/undo is the slice-014 seam** — named, not built (no restore endpoint, no client undo toast, matching the shipped task-delete scope).

### Authorization dispatched by the parent project's visibility — reuse slice 007 unchanged (R3)
Comments carry no visibility/membership of their own; every read/write loads the parent `Task`, resolves its `Project.Visibility`, and dispatches onto the slice-007 `ResolveEffectiveRole`/`RequireRole` branch — **no fork**. Personal/null-`ProjectId` tasks have **no comment surface → 404**. Read = viewer+, post = editor+; non-member → 404, insufficient-role member → 403 (the slice-007 leak boundary).

### Authorship is an object-level grant: RequireRole(Editor) FIRST, author-equality SECOND (R4)
Edit/delete run a strict two-step gate. Role floor first, then `author_id == caller` (a non-author of any role, **including the owner**, → 403). Because membership resolves **live** in step 1, a former member is 404'd **before** the author check — so **FR-066 (membership loss revokes ALL) structurally beats FR-075 (author grant)** with no special-case branch.

### @mention is a typed User-id token; candidacy = current members; persisted in a child table (R6)
`mentionedUserIds` are structured tokens (never scraped from prose), validated server-side against the **current** member roster — a non-member/former-member mention → **422** and no comment is persisted. De-duplicated; a self-mention is allowed but not notified. Persisted as `comment_mentions(comment_id, user_id)`.

### `UserMentioned` outbox event — added-only delta on edit; slice-017 seam (R7)
Post/edit raises `UserMentioned` (pure ids, mirroring `TaskAssigned`) via `DomainEventDispatch.PublishAndClearAsync` before `SaveChangesAsync`. **On edit only newly-added mentions** emit (removals/unchanged emit nothing — no notification spam). This slice registers a **no-op routable handler** so the publish is observable; **slice 017** replaces it with the real notification consumer.

### FR-098/FR-099 content safety — length/empty at the command boundary (422), sanitize at the render boundary (R8)
Server-authoritative length + non-empty at the FluentValidation command boundary → **422**; output sanitized to the "constrained safe subset (plain text + safe markdown)" at the **web render boundary** (the one new web dep — strict allowlist, no raw HTML/script). Stored `body` is raw (so edit round-trips + a later renderer re-sanitizes old rows). CSP + security headers **already exist** and are **reused**.

### No new error code (R9)
`forbidden`(403), `not_found`(404), `validation_failed`(422) are reused; `version_conflict`(409) is unused. The transformer `ErrorCodes` array and the web `ERROR_UX` map stay **unchanged** — the exhaustiveness gate stays green with no edit.

### Time: UTC `timestamptz` + Warsaw relative display via the existing web util (R10)
`created_at`/`edited_at` stored UTC; relative thread display against `Europe/Warsaw` via the existing `date-fns` + `timezone.ts` util — no new date library, no NodaTime, no server-side Warsaw conversion for comments.

### Privacy: `author_id` nullable, FK `ON DELETE SET NULL` (tombstone, NOT cascade) (R11)
The one FK that deliberately breaks house-style cascade parity: on erasure the author becomes a tombstone (`author_id = NULL`) and the comment **survives** where it anchors a thread (FR-085) — a blanket cascade would destroy thread history. The `comment_mentions.user_id` token follows the same residual rule. This slice **models** for anonymization; the slice-015 erasure cascade is a named seam.

### One migration; FR-051 is LIVE (R12)
`AddComments` creates `comments` + `comment_mentions` (FK directions encode ownership vs privacy: `task_id`/`comment_id` CASCADE, `author_id`/`mention.user_id` SET NULL). A real schema change → the backup-before-migrate + CI restore-test gate must actually run — see Complexity Tracking.

### Web: optimistic mutations + lazy thread read; a NEW task detail panel (R13/R14/R15)
`useCommentMutations` is **optimistic + rollback** (the slice-002/004 recipe — comments are the one mutation family the spec routes to optimistic, unlike slice-007 membership). The thread mounts in a **new** task detail panel (no such component exists today). `CommentResponse.canEdit` gates client affordances only (the server R4 gate is the boundary).
