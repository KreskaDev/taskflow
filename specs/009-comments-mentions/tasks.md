# Tasks: Comments & @Mentions

**Input**: Design documents from `/specs/009-comments-mentions/`
**Prerequisites**: plan.md, spec.md, research.md (R1–R15), data-model.md, contracts/openapi.yaml, quickstart.md (all present)

**Tests**: REQUIRED. Constitution v4.0.0 **Principle IX (Authn/Authz) is CONSUMED here** — the comment surface
authorizes by **reusing the slice-007 dispatch-by-visibility policy unchanged** (`ResolveEffectiveRole` / `RequireRole`)
and layers an **object-level authorship grant** (FR-075) on top for edit/delete. **Principle XII is CENTRAL** —
comments are the product's first free-form user content and a stored-XSS surface (FR-098/099). The governance gate
requires **every new data handler to ship an allow AND a deny test**, **plus** this slice ships the **role × operation
deny matrix** (SC-016) as a first-class test artifact. Authorization changes require a **non-author reviewer** before
merge. Test-First is Red-Green-Refactor: **the test task has a LOWER id than the implementation it covers — write it,
watch it fail (RED), then implement (GREEN).**

**Organization**: This slice introduces one **new aggregate** (`Comment`, ENT-08) — its **own** aggregate root, NOT an
owned child of `Task` (R1) — with **two new tables** (`comments` + the `comment_mentions` child collection) via one EF
migration (`AddComments`) → **FR-051 backup-before-migration is LIVE** (the slice-004/007/008 posture). The work splits
into a **Foundational** layer (the `Comment` aggregate + `CommentId` + the typed `comment_mentions` child + the
`UserMentioned` event + the reused-policy `CommentAccessGuards` + persistence + migration + repository + read model —
blocking the story) and **one story**:
- **US-14 — Comments & @Mentions (US-14, P2)**: an editor/owner posts a comment on a shared-project task (AS-01) and
  @mentions a current member (AS-02, emitting `UserMentioned`); a viewer reads the thread but is presented with **no
  composer** (AS-03); a comment's **author — and only the author** — edits/deletes it (AS-04), with membership loss
  overriding the author grant (FR-066 > FR-075).

Comments **consume** the slice-007 authorization branch — comments live **only** on tasks in **shared** projects, so
every read/write loads the parent `Task`, resolves its `Project.Visibility`, and dispatches onto the membership + role
branch (read = viewer+; post = editor+; edit/delete = editor+ **then** author-equality). **No new error code** (R9):
`forbidden`(403), `not_found`(404), `validation_failed`(422) are reused; `version_conflict`(409) is **unused** (comments
are versionless / last-write-wins — R2). This slice **raises** `UserMentioned` (consumed by slice 017), builds the
**optimistic-paint** half of the thread (live propagation is slice 016), **models** the author tombstone (the
erasure cascade is slice 015), and ships the **soft-delete + scheduled `ReapDeletedComment` reaper** substrate for
comment delete (the Constitution-VII 30s-undo MUST; the user-facing restore/undo is slice 014) — all **named seams,
NOT built here** beyond what each requires.

## Phase 3: User Story 14 — Comments & @Mentions (Priority: P2) 🎯

**Goal**: An editor/owner posts a comment on a shared-project task (it appears in the thread with author + timestamp)
and @mentions a current member (notifying them via the `UserMentioned` event); a viewer reads the thread but is
presented with **no composer** and is denied post/edit/delete; a comment's **author — and only the author** — edits or
deletes their own comment, with the thread updating. Every read/write authorizes through the **reused** slice-007
membership + role branch; edit/delete run `RequireRole(Editor)` **FIRST** then author-equality, so a non-author of any
role (**including the owner**) → 403 and a former member → 404 (FR-066 structurally beats FR-075).

**Independent Test**: As editor **E** post a comment on a shared task **T** → appears with author + timestamp;
@mention **E2** → a `UserMentioned` event is raised; as viewer **V** open **T** → full thread, **no composer**, and a
direct post → 403; as **E** edit then delete own comment → the thread updates; as owner **A** (non-author) edit/delete
**E**'s comment → 403; remove **E** from **T**'s project, then as **E** read/edit/delete → 404; post an empty /
over-length body → 422; @mention a non-member → 422; a `<script>` body renders **inert**.

## Implementation Strategy

### MVP
Foundational (the `Comment` aggregate + the reused-policy `CommentAccessGuards` + the `UserMentioned` event + migration)
→ US-14 backend (the three commands + the thread query + the SC-016 deny matrix) → **T028 gen:api** → US-14 web (the
task detail panel + the thread/composer/mention-picker + the **optimistic** comment mutations + the safe-markdown
renderer) → **STOP & VALIDATE** the quickstart (post/mention, viewer read-only, author edit/delete, membership-loss
override, content safety) → Polish. The authorization consumption (reused policy + author grant ordering) and the
content-safety split (422 at the command boundary + sanitize at the render boundary) are the load-bearing increments.

### Notes
- **Authorization is CONSUMED, not originated** (Principle IX): comments **reuse** the slice-007 `RequireRole` dispatch unchanged (R3, no fork) — read = viewer+, post = editor+; edit/delete run **`RequireRole(Editor)` FIRST then author-equality SECOND** (R4). Every new data handler ships an **allow AND a deny** test, **plus** the **role × operation deny matrix** (SC-016) as a first-class suite. **Authorization changes require a non-author reviewer** (governance gate).
- **Deny-shape rule** (R3/R4): **non-member / former member / personal-or-foreign task / foreign comment → 404 `not_found`** (existence not disclosed across the membership boundary — Constitution XII); **member with insufficient role** (viewer post/edit/delete) → **403 `forbidden`**; **non-author with sufficient role** (owner/editor editing someone else's comment) → **403** (FR-075 — role does not override authorship). Because the role floor resolves membership **live** in step 1, a former member is 404'd **before** the author check — **FR-066 structurally beats FR-075**.
- **`Comment` is its OWN aggregate root, versionless** (R1/R2): comment writes do **not** touch `Task.Version`/`Project.Version` (the parent is loaded read-only, for authorization only); edit/delete are **last-write-wins** — **no `version` field, no 409** (one fewer reused code than slice 007).
- **Delete = soft-delete + scheduled reaper** (R5, Constitution VII 30s-undo): `DeleteComment` stamps `deleted_at` (`Comment.SoftDelete`) and publishes a scheduled `ReapDeletedComment` (+30s) off the durable `comment-reaper` queue — the **`DeleteTask`/`ReapDeletedTask` mirror**; the reaper hard-purges only if still-tombstoned at the scheduled instant (µs match — restore-aware/idempotent; versionless, so no `Task.Version` backstop analog). The thread read filters `deleted_at IS NULL`; delete is version-free/idempotent (own already-deleted → 204 no-op). The user-facing restore/undo is the **slice-014** seam (not built — no restore endpoint, no client undo toast, matching task-delete's shipped scope).
- **@mention is a typed User-id token** (R6): `mentionedUserIds` validated server-side against the **current** member roster (non-member → **422**, no comment persisted); de-duplicated; a self-mention is allowed but not notified; never scraped from prose.
- **`UserMentioned` outbox event** (R7): raised on post (full set minus self) and edit (**added-only delta** — removals/unchanged emit nothing); a registered **no-op routable handler** makes the publish observable; **slice 017** consumes it additively.
- **Content safety split** (R8/FR-098/099): length/non-empty enforced **server-authoritatively** at the FluentValidation command boundary → **422** (an empty body creates no thread entry); output sanitized to the safe subset (plain text + safe markdown) at the **web render boundary** (the one new web dep — strict allowlist); CSP + security headers **already exist** and are **reused**.
- **Privacy: author tombstone** (R11): `comments.author_id` is **nullable / `ON DELETE SET NULL`** (NOT cascade — the one FK that breaks house-style parity) so account erasure tombstones the author without destroying thread history; the mention token follows the same residual rule; the read model renders null author as "Deleted user". This slice **models** for anonymization; the slice-015 cascade is a named seam.
- **Optimistic web** (R14): comments are the one mutation family the spec routes to the **optimistic + rollback** recipe (unlike slice-007 membership); the thread mounts in a **NEW** `TaskDetailPanel`; live inbound propagation is the slice-016 seam.
- **One migration; FR-051 LIVE** (R12): `AddComments` (two tables, no DDL on existing tables); the backup + restore-test gate must run green.
- **No new error code** (R9); **no NodaTime** (comment timestamps are plain UTC `timestamptz`; relative-time display is a web concern via the existing `date-fns` util — R10).
